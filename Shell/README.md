# Unified OpenShift Health Check Suite

This package unifies the previous `ocp-4.18` and `ocp-4.18-deep` folders into a single full Health Check workflow for OpenShift 4.18 and later.

## Target structure

```text
/
├── ocp-healthcheck.sh                    # Main unified execution entrypoint
├── ocp-healthcheck.env.example           # Variables template
├── redaction-patterns.example.txt        # Optional sanitization patterns
├── latest/
│   └── ocp-healthcheck-latest.sh         # Latest wrapper
├── lib/
│   └── ocp-healthcheck-lib.sh            # Shared Bash library
├── reports/
│   └── ocp-report-renderer.py            # HTML/Markdown/CER/report renderer
├── ocp-4.18/
│   └── ocp418-healthcheck-full.sh        # OCP 4.18 entrypoint
├── ocp-4.19/
│   └── ocp419-healthcheck-full.sh        # OCP 4.19 entrypoint
├── ocp-4.20/
│   └── ocp420-healthcheck-full.sh        # OCP 4.20 entrypoint
└── ocp-4.21/
    └── ocp421-healthcheck-full.sh        # OCP 4.21 entrypoint
```

## What the unified script collects

The script is read-only except for local file generation. It collects:

- `run.log`
- `summary.txt`
- `command-index.tsv`
- `health-report.html`
- `health-report.md`
- `raw/` command output
- `logs/` logs from problematic pods
- `describes/` describes from problematic pods and namespace objects
- `must-gather/` generated by `oc adm must-gather`
- all listable API resources through `oc api-resources --verbs=list`
- all CRD definitions and CRD instances
- platform baseline: ClusterVersion, ClusterOperators, nodes, MCP, CSR, APIService
- core component namespaces
- network deep review: DNS, ingress, routes, services, endpoints, NetworkPolicy, AdminNetworkPolicy, EgressIP, EgressFirewall, NAD, NMState, SR-IOV
- storage deep review: StorageClasses, PV, PVC, VolumeAttachments, CSI, registry storage, monitoring storage, ODF resources
- OLM: Subscriptions, CSVs, InstallPlans, CatalogSources
- security: SCC, OAuth, ClusterRoleBindings, secret metadata without secret data, API server encryption config
- AI/AIOps candidates: AI namespaces, GPU/accelerator signals, model-serving resources and related operators
- namespace deep review: quotas, LimitRanges, NetworkPolicies, secrets metadata, ConfigMaps keys, deployments, pods, services, routes, HPA, PDB and RBAC

## Quick start

```bash
cd ocp-healthcheck-unified
chmod +x ocp-healthcheck.sh latest/ocp-healthcheck-latest.sh ocp-4.18/ocp418-healthcheck-full.sh reports/ocp-report-renderer.py
cp ocp-healthcheck.env.example ocp-healthcheck.env
cp redaction-patterns.example.txt redaction-patterns.txt
vi ocp-healthcheck.env
vi redaction-patterns.txt
oc login https://api.<cluster>:6443
./latest/ocp-healthcheck-latest.sh --env-file ./ocp-healthcheck.env --cluster-name non-prod-ocp --client-label KPMG
```

For OCP 4.18:


## Focused namespace review

To analyze specific namespaces only:

```bash
./latest/ocp-healthcheck-latest.sh \
  --env-file ./ocp-healthcheck.env \
  --cluster-name non-prod-ocp \
  --client-label KPMG \
  --target-namespaces apm0006923-non-prod,aiops-ns,model-serving-ns
```

## Reading the outputs

Start with:

```bash
cat ocp-healthcheck-runs/<run-dir>/summary.txt
xdg-open ocp-healthcheck-runs/<run-dir>/health-report.html
xdg-open ocp-healthcheck-runs/<run-dir>/report/errors-<cluster-name>.html
less ocp-healthcheck-runs/<run-dir>/report/cer-fill-sections.md
```

Then review the CSV files:

```bash
column -s, -t ocp-healthcheck-runs/<run-dir>/csv/findings.csv | less -S
column -s, -t ocp-healthcheck-runs/<run-dir>/csv/backlog.csv | less -S
column -s, -t ocp-healthcheck-runs/<run-dir>/csv/errors-criticality.csv | less -S
column -s, -t ocp-healthcheck-runs/<run-dir>/csv/namespace-review.csv | less -S
column -s, -t ocp-healthcheck-runs/<run-dir>/csv/workload-review.csv | less -S
```

## CER files

Use this file to fill report sections:

```text
report/cer-fill-sections.md
```

It contains draft content for:

- Executive Summary
- Engagement Requirement Criteria
- Journal
- Knowledge Transfer
- Summary of Findings
- Technical Next Steps
- Critical Findings and Remediation Annex

## Backlog

The remediation backlog is generated as:

```text
csv/backlog.csv
report/backlog.csv
```

Columns include priority, severity, likelihood, complexity, category, namespace, object, action, rationale, remediation, owner, status and evidence.

## Important notes

- The script does not intentionally export secret values. Secret collection uses metadata and removes `.data` when `jq` is available.
- `must-gather` can be large and take several minutes.
- `COLLECT_ALL_API_RESOURCES=true` and `COLLECT_ALL_CRD_INSTANCES=true` can produce a large amount of data on large clusters.
- Review `redaction-patterns.txt` before sharing outputs.
- The generated recommendations are automated triage suggestions and must be reviewed by a consultant before customer delivery.
